# moai-note 아키텍처 개요

> 시작점 문서. 구조를 파악할 때 여기서 시작해 각 절로 이동한다.
> 사실값(포트·경로·구성)은 코드 확인 후 기재한다 — 추측으로 쓰지 않는다.

## 1. 무엇인가

**노션형 블록 에디터와 그 저장 백엔드.** 호스트 페이지에 임베드해서 쓰는 독립 제품이다.

첫 소비자는 SeedAI 챗봇 위젯이지만, **SeedAI에 의존하지 않는다.** 인증·저장·설정을 자체 보유하며
다른 호스트에도 같은 방식으로 붙는다.

## 2. 모듈 구성

| 모듈 | 스택 | 역할 |
|---|---|---|
| `moai-note-editor-web` | TypeScript + TipTap(ProseMirror) + Vite | 에디터. `embed.js` 단일 번들로 빌드, **API 서버가 정적 제공** |
| `moai-note-api` | TypeScript + Node (포트 **7100**) | 문서 저장 + 토큰 발급 + REST + MCP |

모듈은 필요해질 때 형제 디렉토리로 추가한다. 지금은 이 둘뿐이다.

## 3. 전체 구조

```
[호스트 페이지]  예: SeedAI 챗봇 위젯
   │  <script src="https://<moai-note>/embed.js">   ← 필요할 때만 로드
   │  MoaiNote.mount(el, { documentId, token })
   │
   │  Shadow DOM 안에 에디터 생성 (호스트 CSS와 상호 무간섭)
   │
   │  https + Bearer 단기 토큰
   ▼
[moai-note-api] :7100
   ├ static/       embed.js + 자산 정적 제공        ★ 호스트는 번들을 안고 가지 않는다
   ├ http/        HTTP 서버 + TLS + CORS 화이트리스트
   ├ auth/        토큰 발급·검증 + 소유권 검증     ★ REST·MCP 공통 관문
   ├ rest/        REST 컨트롤러  ─┐
   ├ mcp/         MCP 도구        ─┤ 얇은 어댑터
   ├ service/     문서·리비전 서비스 ◄┘  ★ 두 표면이 공유하는 단일 구현
   └ storage/     저장 계층 (SQLite, 교체 가능)
```

## 4. 설계 원칙

이 네 가지는 타협하지 않는다.

### 4-1. 인증 관문은 하나

REST와 MCP가 **같은 관문**을 지난다. 표면별로 인증을 따로 구현하면 한쪽이 반드시 뚫린다.

> SeedAI에서 MCP `/http`를 무인증(`permitAll`)으로 열어둔 사례가 미해결 부채로 남아 있다.
> 같은 구조를 새로 만들지 않는다.

### 4-2. 로직은 service에만

REST 컨트롤러와 MCP 도구는 **입출력 변환만** 한다.

- MCP 도구가 REST를 HTTP로 재호출하는 구조 금지
- 컨트롤러가 storage를 직접 만지는 구조 금지

### 4-3. 시크릿은 브라우저에 두지 않는다

`client_secret`은 **서버 간 호출 전용**이다. 브라우저는 단기 토큰만 갖는다.

```
[호스트 백엔드] ──client_id + client_secret + 사용자식별자──► moai-note-api
                ◄──────────── 단기 액세스 토큰 ─────────────
      │  단기 토큰만 전달
      ▼
  [브라우저]  ──Bearer 단기 토큰──►  REST
  [에이전트]  ──Bearer 단기 토큰──►  MCP
```

이 구조 덕분에 moai-note는 **호스트가 누구인지 알 필요가 없다.** 호스트가 자기 사용자 체계로
인증한 뒤 그 결과를 사용자 식별자로 넘기기만 하면 된다.

### 4-4. 소유권은 서버가 판단한다

문서 접근 권한은 **토큰에서 얻은** 소유자 식별자로만 판정한다.
클라이언트가 요청 본문·쿼리로 보낸 소유자 값은 신뢰하지 않는다.

## 5. 에디터 임베드 계약

**iframe이 아니라 JS로 호스트 DOM에 직접 마운트한다.** 호스트 테마·높이와 자연스럽게 어울리고
postMessage 계약이 필요 없다.

```html
<script src="https://<moai-note>/embed.js"></script>
<div id="note-1"></div>
<script>
  MoaiNote.mount('#note-1', { documentId: 'xxx', token: '<단기토큰>' });
</script>
```

| 항목 | 내용 |
|---|---|
| 로드 | **API 서버가 `embed.js`를 정적 제공**. 호스트는 스크립트 태그 하나만 건다 |
| 프레임워크 | **비의존** — 호스트에 React 등을 요구하지 않는다 |
| 스타일 격리 | **Shadow DOM** — 아래 참조 |
| 마운트/해제 | 해제 시 DOM·이벤트·리스너가 남지 않아야 한다 |
| 다중 인스턴스 | 한 페이지에 여러 개가 공존해도 간섭하지 않는다 |
| 내용 | 호스트가 내용을 넘기지 않는다. **`documentId`로 API에서 불러온다** |

상세 계약(함수명·옵션·이벤트)은 요구사항의 I(인터페이스 계약) 문서에서 확정한다.

### 왜 Shadow DOM인가

호스트 CSS에 전역 리셋이 있으면 에디터 내부까지 덮인다.
실제로 SeedAI 챗봇 위젯 CSS에는 `* { box-sizing; margin; padding }` 이 있다.

Shadow DOM은 **iframe 수준의 CSS 격리**를 주면서도 같은 문서 안에 있어
높이·테마가 자연스럽게 동작한다. 양방향 오염을 모두 막는다.

## 6. 배포

**호스트에 번들을 복사하지 않는다.** API 서버가 `embed.js`를 정적 제공한다.

```
moai-note-editor-web/dist/  ──►  moai-note-api 가 /embed.js 로 제공  ──►  호스트는 <script> 한 줄
```

번들 복사 방식을 쓰지 않는 이유:

- API 계약이 바뀌면 **호스트를 전부 재배포**해야 한다
- 누락되면 구버전 에디터가 신버전 API를 호출해 조용히 깨진다
- 호스트가 늘어날수록 배포 비용이 선형으로 증가한다

서버 제공 방식은 **서버 갱신만으로 모든 호스트에 반영**된다.
버전 고정이 필요한 호스트를 위해 버전 경로(`/v1/embed.js` 등)를 둘지는 I에서 확정한다.

## 7. 포트

| 포트 | 용도 |
|---|---|
| **7100** | `moai-note-api` (REST + MCP) |

**71xx가 moai-note 대역이다.** 다른 제품의 번호 체계를 따르지 않는다 — 독립 제품이므로
자기 대역을 갖는다. 모듈이 늘어나면 7101, 7102 …로 확장한다.

기본값일 뿐이며 `MOAI_NOTE_PORT`로 변경할 수 있다.
같은 개발 머신에서 다른 제품과 함께 뜨므로, 포트를 정할 때는 문서가 아니라
**실제 점유 상태를 확인**한다(`lsof -nP -iTCP -sTCP:LISTEN`).
