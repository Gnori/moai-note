## 1. 요구사항 분석

### 1.1 문제 정의

**문서의 정본(定本)이 어디에도 없다.**

에이전트가 만든 문서는 대화 본문에 마크다운으로 흩어져 있다. 대화는 흘러가는 기록이지 문서 저장소가
아니므로 이렇게 된다.

| 문제 | 현상 |
|---|---|
| **정본 부재** | 같은 문서가 대화 여러 곳에 조각으로 존재한다. 어느 것이 최신인지 알 수 없다 |
| **편집 수단 없음** | 챗봇 위젯은 R-1029로 마크다운 렌더링이 확장됐지만 **읽기 전용**이다 |
| **맥락 단절** | 고치려면 포털의 워드 에이전트 화면(Univer Docs)으로 이동해야 한다. 고친 뒤 "이렇게 바꿨어"를 대화에 다시 설명해야 한다 |
| **에이전트가 손댈 수 없음** | 에이전트는 문서를 **만들어 뱉을** 뿐, 기존 문서를 열어 고칠 방법이 없다 |

마지막 항목이 특히 크다. 사람은 편집기로, 에이전트는 대화로 각자 문서를 다루는데 **둘이 같은 문서를
보고 있지 않다.**

### 1.2 목표 및 성공 지표

**moai-note가 문서의 정본을 소유하고, 사람과 에이전트가 같은 문서를 각자의 방식으로 다룬다.**

구글 문서처럼 — 문서는 moai-note에 있고, 호스트(챗봇 위젯 등)는 그것을 **끼워 넣어 보여줄 뿐**이다.
대화가 실어 나르는 것은 문서 내용이 아니라 **문서 참조**다.

```
        [에이전트]                          [사람]
            │ MCP                             │ 임베드된 에디터
            ▼                                 ▼
        ┌───────────────────────────────────────┐
        │        moai-note  (문서 정본)          │
        └───────────────────────────────────────┘
```

| 목표 | 성공 지표 |
|------|-----------|
| **문서 정본을 moai-note가 소유** | 대화에는 문서 참조만 실린다. 내용은 moai-note에서 온다 |
| **사람·에이전트가 같은 문서를 다룬다** | 에이전트가 MCP로 고친 내용이 사용자 화면에 보이고, 그 반대도 성립한다 |
| 대화 안에서 문서 열람·편집 | 화면 전환 없이 편집 → 저장까지 완료 |
| 노션 수준의 편집 경험 | 블록 타입 전환, 버블 툴바, 슬래시 커맨드 동작 |
| 호스트 독립성 | 챗봇 위젯 외 다른 호스트에도 **동일 방식으로 임베드** 가능 |
| 호스트 부담 최소화 | 호스트는 번들을 안고 가지 않는다 — 참조만 넣으면 된다 |

### 1.4 제약 조건

- **별도 저장소** — `moai-note`는 `/Users/jackylim/Developments/AI/moai-note`에 둔다. SeedAI 저장소 밖이므로 **외부 저장소로 취급**하고 변경분은 별도 커밋/PR로 관리한다.
- **임베드는 JS 방식 (확정)** — iframe이 아니라 **호스트 DOM에 직접 마운트**한다. 호스트 테마·높이와 자연스럽게 어울리고 postMessage 계약이 필요 없다.
- **에디터 스크립트는 moai-note 서버가 제공 (확정)** — 호스트가 번들을 복사해 안고 가지 않는다. 호스트는 `<script src="https://<moai-note>/embed.js">` 하나만 건다.
  → 번들 복사 방식이면 API 계약이 바뀔 때마다 **호스트 3곳을 전부 재배포**해야 하고, 누락 시 구버전 에디터가 신버전 API를 호출해 깨진다. 서버 제공 방식은 서버 갱신만으로 끝난다.
- **Shadow DOM으로 스타일 격리 (확정)** — 챗봇 위젯 CSS에 `* { box-sizing; margin; padding }` **전역 리셋**이 있어 같은 DOM에 넣으면 에디터 내부까지 덮인다. 반대 방향 오염도 막아야 한다.
- **npm 레지스트리 미사용** — 사내 레지스트리가 없다. 배포는 서버 정적 제공으로 갈음한다.
- **호스트는 번들러 없는 vanilla JS** — 챗봇 위젯이 그렇다. 따라서 `embed.js`는 **전역 진입점 하나로 즉시 사용 가능**해야 한다.
- **React 강제 금지** — 호스트에 React 런타임을 요구하지 않는다. 에디터 코어는 프레임워크 비의존으로 번들한다.
- **새니타이즈 경계** — 위젯의 모든 HTML 주입은 DOMPurify를 거친다(R-1029). 에디터 DOM은 이 경로를 타지 않는다(Shadow DOM 안에서 DOM API로만 생성).
- **백엔드는 Node** — 문서 저장을 위해 `moai-note-api`를 Node로 만든다. SeedAI 백엔드(Java/Spring, Python)와 별개이며 SeedAI DB를 공유하지 않는다.
- **SeedAI에 의존하지 않는다 (확정)** — `moai-note`는 독립 제품이다. **Keycloak을 쓰지 않고**, SeedAI DB·설정·인증 체계를 참조하지 않는다. SeedAI 챗봇 위젯은 **여러 호스트 중 하나**일 뿐이며, 다른 호스트에도 같은 방식으로 붙일 수 있어야 한다.
  → 따라서 인증은 **자체 체계**로 갖춰야 한다(3.5).
- **포트 7100 — 자체 대역 (확정)** — moai-note는 독립 제품이므로 다른 제품의 번호 체계를 따르지 않고 **자기 대역(71xx)** 을 쓴다. 모듈이 늘어도 71xx 안에서 확장한다.
  기본값일 뿐이며 `MOAI_NOTE_PORT`로 변경 가능하다. (8060은 개발 머신에서 이미 다른 프로세스가 점유 중이라 사용 불가 — 2026-07-28 확인)
- **브라우저에서 직접 호출된다** — 위젯이 곧 클라이언트다. 따라서 API는 **인터넷에 노출되는 것으로 간주**하고 설계해야 한다(1.5 최상위 리스크).
- **REST와 MCP를 모두 제공** — 사람(위젯)은 REST로, 에이전트는 MCP(streamable HTTP)로 같은 기능을 쓴다. 두 표면이 **같은 서비스 계층을 공유**해야 하며 로직이 갈라져서는 안 된다.
- **HTTPS 지원 필수** — 위젯이 https 페이지에 임베드되므로 http API 호출은 브라우저가 차단한다(혼합 콘텐츠). 개발 환경에서도 https로 띄울 수 있어야 한다.

### 2.2 기능 상세 및 인수 기준

#### F-001 프로젝트 골격 및 빌드

- [ ] `npm run build`가 `dist/embed.js` 단일 파일을 만든다 (CSS는 번들에 포함해 Shadow root에 주입)

- [ ] `npm run dev`로 `demo/` 페이지가 뜨고, 백엔드 없이 에디터를 조작할 수 있다
- [ ] 번들 용량을 README에 기록한다(지연 로드 판단 근거)

#### F-002 에디터 코어

- [ ] 지원 블록: 문단, 제목 1~3, 순서 없는 목록, 순서 있는 목록, 체크리스트, 인용, 코드블록, 표, 구분선
- [ ] 인라인 서식: 굵게, 기울임, 취소선, 인라인 코드, 링크
- [ ] 되돌리기/다시하기가 동작한다
- [ ] **한글 입력(IME) 중 커서·조합이 깨지지 않는다** — 조합 중 되돌리기, 조합 중 서식 적용 확인
- [ ] 붙여넣기 시 서식이 지원 블록으로 정규화된다(임의 HTML이 그대로 들어오지 않음)

#### F-003 버블 툴바

- [ ] 텍스트를 선택하면 선택 영역 근처에 툴바가 나타난다
- [ ] 굵게 / 기울임 / 링크 / 블록 타입 전환(Text·제목1~3·목록·체크리스트)을 제공한다
- [ ] 선택 해제 시 사라진다
- [ ] 좁은 폭에서 툴바가 화면 밖으로 나가지 않는다

#### F-004 슬래시 커맨드

- [ ] 빈 줄에서 `/`를 입력하면 블록 삽입 메뉴가 뜬다
- [ ] 키보드 위/아래·Enter로 선택할 수 있다
- [ ] 한글 입력 중에는 오작동하지 않는다
- [ ] Esc로 닫힌다

#### F-005 마크다운 왕복

- [ ] 마크다운 문자열로 문서를 연다
- [ ] 편집 후 마크다운 문자열을 얻는다
- [ ] **왕복 무손실** — 지원 문법(F-002 목록 + 링크)이 원문과 동등하게 보존된다. 왕복 테스트를 자동화한다
- [ ] 지원하지 않는 문법은 **손실 없이 원문 보존**하거나, 손실이 불가피하면 문서화한다

#### F-006 읽기/편집 모드

- [ ] 기본은 **읽기 전용**이며 편집 UI가 노출되지 않는다
- [ ] `Edit` 조작으로 편집 모드에 진입한다
- [ ] 읽기 모드의 서식이 R-1029 위젯 렌더 결과와 **시각적으로 일관**된다(글꼴·간격·색)
- [ ] 편집 모드에서 읽기 모드로 되돌릴 수 있다

#### F-007 임베드 계약

- [ ] 전역 진입점 하나로 컨테이너에 마운트한다 — `MoaiNote.mount(el, { documentId, token })`
- [ ] **호스트가 문서 내용을 넘기지 않는다** — `documentId`로 API에서 불러온다
- [ ] 에디터 UI는 **Shadow root 안에서만** 생성한다 — 호스트 전역 CSS(`* { }` 리셋)의 영향을 받지 않고, 호스트를 오염시키지도 않는다
- [ ] 해제(destroy) 시 DOM·이벤트·리스너가 남지 않는다 (여러 번 마운트/해제해도 누수 없음)
- [ ] 내용 변경 시 콜백으로 알린다 — 호스트가 저장 연동을 붙일 수 있는 지점
- [ ] 한 페이지에 **여러 인스턴스**가 공존해도 서로 간섭하지 않는다
- [ ] 상세 계약(함수명·옵션·이벤트)은 I 문서에서 확정한다

#### F-008 문서 액션

- [ ] 본문 전체를 클립보드로 복사
- [ ] 마크다운 파일로 내려받기
- [ ] 전체화면 보기 — 위젯의 좁은 폭에서 벗어나 편집

#### F-009 테마 연동

- [ ] 호스트가 지정한 테마(다크/라이트)를 따른다
- [ ] 색상은 하드코딩하지 않고 CSS 변수로 노출해 호스트가 덮어쓸 수 있다

#### F-010 `embed.js` 정적 제공

- [ ] API 서버가 `embed.js`(및 필요한 자산)를 정적 경로로 제공한다
- [ ] **호스트에 번들을 복사하지 않는다** — 서버 갱신만으로 모든 호스트에 반영된다
- [ ] 적절한 캐시 헤더를 둔다 — 갱신이 즉시 반영되면서도 매 요청 재다운로드하지 않도록
- [ ] 버전 고정 경로(`/v1/embed.js` 등) 제공 여부는 I에서 확정한다

#### F-011 위젯 임베드

- [ ] 위젯이 대화 안의 **문서 참조를 감지**해 에디터를 마운트한다 (참조 형식은 I에서 확정)
- [ ] 문서 참조가 없으면 **`embed.js`를 로드하지 않는다** (Network 요청 0건)
- [ ] 에디터 로드 실패 시 **문서 링크/카드로 폴백**한다 — 사용자가 문서에 접근할 길이 남는다
- [ ] 에디터가 만드는 DOM은 위젯 새니타이즈 경로를 타지 않는다(Shadow DOM)
- [ ] 에디터 CSS가 위젯·호스트 스타일을 오염시키지 않으며, 그 역도 성립한다
- [ ] 위젯에는 **통합 코드만** 들어간다 — 에디터 번들을 사본 3벌에 넣지 않는다

#### F-012 저장 API (REST)

- [ ] 문서 생성 / 단건 조회 / 수정 / 삭제 / 목록 조회를 제공한다
- [ ] 문서는 **마크다운 본문 + 메타데이터**(제목, 소유자, 생성·수정 시각)로 저장된다
- [ ] 동시 수정 충돌을 감지한다 — 마지막 수정 시각 또는 리비전 번호 불일치 시 409
- [ ] 잘못된 요청에 일관된 오류 형식을 반환한다
- [ ] 상세 계약(경로·DTO·오류 코드)은 I 문서에서 확정한다

#### F-013 자체 토큰 발급·인증 (REST·MCP 공통)

> **이 요구사항의 최우선 항목.** SeedAI에서 MCP `/http`를 무인증으로 열어둔 부채(R-3328)가 아직 미해결이다. 같은 구조를 새로 만들지 않는다.
>
> `moai-note`는 SeedAI와 무관한 독립 제품이므로 **인증 체계를 자체 보유**한다(Keycloak 미사용).

**발급 체계**

- [ ] **클라이언트 등록** — 호스트별로 `client_id` / `client_secret`을 발급·폐기할 수 있다
- [ ] **토큰 발급 엔드포인트** — `client_secret`으로 **단기 액세스 토큰**을 교환한다
- [ ] 토큰 발급 시 호스트가 **최종 사용자 식별자**를 함께 전달하고, 그 값이 토큰에 담겨 문서 소유자가 된다
- [ ] **`client_secret`은 서버 간 호출에서만 쓴다** — 브라우저에 노출되는 구성을 금지한다. 위젯은 호스트로부터 받은 **단기 토큰만** 보유
- [ ] 토큰 만료 시간을 설정으로 둔다. 만료된 토큰은 거부된다
- [ ] 토큰 서명 비밀키는 환경변수로 받는다

**검증·인가**

- [ ] **무인증 접근이 불가능하다** — 토큰 없는 요청은 401
- [ ] 위조·만료 토큰은 401
- [ ] **MCP 엔드포인트도 동일하게 인증**된다 — REST만 막고 MCP를 여는 구성을 금지한다
- [ ] 문서 접근은 **토큰에서 얻은** 소유자 기준으로 서버가 검증한다. 클라이언트가 보낸 식별자를 신뢰하지 않는다
- [ ] 남의 문서 조회·수정·삭제 시도가 403으로 차단됨을 테스트로 증명한다
- [ ] CORS는 **오리진 화이트리스트**로 제한한다 — 와일드카드(`*`) 금지
- [ ] 인증 실패·권한 위반이 로그에 남는다(토큰·시크릿 원문은 남기지 않음)

#### F-014 HTTPS 지원

- [ ] 설정으로 **http / https 기동을 선택**할 수 있다
- [ ] 개발 환경에서 자체 서명 인증서로 https 기동이 가능하다
- [ ] 운영은 리버스 프록시가 TLS를 종단하는 구성도 지원한다(`X-Forwarded-Proto` 인식)
- [ ] https 페이지에 임베드된 위젯에서 **혼합 콘텐츠 차단 없이** 호출된다
- [ ] 인증서 경로·비밀번호는 **환경변수**로만 받는다 (저장소에 커밋 금지)

#### F-015 MCP 서버 (streamable HTTP)

- [ ] REST가 제공하는 기능을 **모두** MCP 도구로 제공한다 — 기능 격차가 없어야 한다
- [ ] streamable HTTP 방식으로 노출한다
- [ ] 각 도구에 용도·파라미터·반환을 설명하는 스키마가 있다
- [ ] **REST 컨트롤러와 MCP 도구가 같은 서비스 계층을 호출한다** — 로직 중복·분기 금지
- [ ] F-013의 인증이 동일하게 적용된다
- [ ] 도구 목록·설명은 I 문서에서 확정한다

#### F-016 리비전 관리

- [ ] 문서를 수정하면 이전 내용이 리비전으로 보존된다
- [ ] 리비전 목록(시각·작성자)을 조회할 수 있다
- [ ] 특정 리비전 내용을 조회하고 되돌릴 수 있다
- [ ] 리비전 보관 정책(개수 또는 기간 상한)을 설정으로 둔다 — 무한 증가 방지

#### F-017 에디터↔저장 연동

- [ ] 문서 식별자로 내용을 불러와 에디터에 표시한다
- [ ] 편집 결과를 저장한다 — 저장 시점(수동/자동)은 I에서 확정
- [ ] 저장 실패 시 사용자에게 알리고 **입력 내용이 사라지지 않는다**
- [ ] 저장 충돌(409) 시 사용자가 상황을 알 수 있다
- [ ] 네트워크 없이도 편집 자체는 계속 가능하다

| 마크다운 변환 | TipTap 확장 + 직렬화기 | F-005 왕복 무손실 요건 |
| 언어 | TypeScript | 임베드 계약·API 계약을 타입으로 고정 |

**백엔드 (`moai-note-api`)**

| 구분 | 선택 | 근거 |
|------|------|------|
| 런타임 | **Node** | 요구자 지정. 에디터와 언어·타입 정의를 공유할 수 있다 |
| 언어 | TypeScript | REST·MCP가 같은 서비스 계층을 쓰도록 타입으로 강제(F-015) |
| HTTP | Express 또는 Fastify | 둘 다 https 기동·프록시 인식이 표준. I 단계에서 확정 |
| MCP | `@modelcontextprotocol/sdk` (streamable HTTP) | MCP 공식 SDK. 전송 방식이 SeedAI의 기존 MCP(`/http`)와 같아 클라이언트 설정이 일관됨 |
| 인증 | **자체 토큰 발급 (JWT 서명·검증)** | SeedAI·Keycloak에 의존하지 않는 독립 제품 요건(1.4). 클라이언트 등록 → 시크릿 교환 → 단기 토큰 |
| 저장소 | **SQLite (파일 기반)** | 별도 DB 서버 불필요, 리비전 저장에 충분. **저장 계층을 추상화**해 나중에 교체 가능하게 둔다 |
| TLS | Node 내장 https + 프록시 종단 지원 | F-014 |

**저장소 선택 근거**: SeedAI의 MSSQL을 쓰면 외부 프로젝트가 SeedAI DB에 직접 붙어 경계가 무너진다. 독립 저장소를 두고, 운영 전환 시 저장 계층만 교체한다.

**검토했으나 채택하지 않음**

| 후보 | 제외 사유 |
|---|---|
| BlockNote | 노션형 UI가 기본 내장이라 가장 빠르지만 **React 의존**이 강해 vanilla 위젯에 React 런타임을 끌고 와야 함 |
| Lexical | 가볍고 구조는 깔끔하나 마크다운 왕복·표 등 **직접 구현 부담**이 큼 |
| contenteditable 직접 구현 | **한글 IME·되돌리기·붙여넣기 정규화**를 전부 자체 해결해야 함 — 1.5의 최상위 리스크 |
| Univer Docs (기존) | 워드프로세서 모델이라 마크다운 흐름과 어긋나고 무겁다(1.1 문제 정의) |

### 3.3 아키텍처 설계

```
[moai-note-editor-web]                    [seed-ai-agent-client-web-ui]
  src/                                      core/renderers.js
   ├ core      에디터 인스턴스                 └ note 렌더러
   ├ blocks    블록 확장                          ├ detect  문서 블록 탐지
   ├ ui        버블 툴바 / 슬래시 메뉴            ├ load    dist 지연 로드
   ├ markdown  왕복 변환                          └ render  컨테이너 생성 후 마운트
   ├ client    저장 API 호출 (F-017)
   └ index     전역 진입점(임베드 계약) + Shadow DOM 마운트
        │
   build ▼
   dist/embed.js  ──► API 서버가 정적 제공 ──► 호스트는 <script> 한 줄
        │
        │  https (Bearer 토큰)
        ▼
[moai-note-api]  :7100
   ├ static/        embed.js 정적 제공 (F-010)
   ├ http/          Express|Fastify + TLS + CORS 화이트리스트
   ├ auth/          자체 토큰 발급·검증 + 소유권 검증           ★ REST·MCP 공통 관문
   ├ rest/          REST 컨트롤러   ─┐
   ├ mcp/           MCP 도구         ─┤ 얇은 어댑터
   ├ service/       문서·리비전 서비스 ◄┘  ★ 두 표면이 공유하는 단일 로직
   └ storage/       저장 계층 (SQLite, 교체 가능)
```

| 컴포넌트 | 역할 |
|----------|------|
| 전역 진입점 | 마운트/해제/내용 입출력/변경 콜백 — 호스트가 아는 유일한 표면 |
| 마크다운 변환 | 문서 모델 ↔ 마크다운. 저장 형식이 곧 마크다운이므로 이 경계가 저장 계약과 직결된다 |
| 위젯 note 렌더러 | R-1029 렌더 레지스트리(`{id, detect, load, render}`)에 등록 — 기존 지연 로드 구조를 그대로 재사용 |
| **auth 관문** | REST·MCP **모든 요청**이 지나는 단일 지점. 여기를 우회하는 경로를 만들지 않는다 |
| **service 계층** | 문서 CRUD·리비전의 **유일한 구현**. REST 컨트롤러와 MCP 도구는 입출력 변환만 담당 |
| **storage 계층** | SQLite 구현. 인터페이스로 분리해 교체 가능 |

**설계 원칙 2가지**

1. **인증은 표면별로 두지 않는다** — REST와 MCP가 각자 인증을 구현하면 한쪽이 반드시 뚫린다. 공통 관문 하나만 둔다.
2. **로직은 service에만 둔다** — MCP 도구가 REST를 HTTP로 재호출하거나, 컨트롤러가 저장소를 직접 만지는 구조를 금지한다.

### 3.4 데이터 영향 요약

- **SeedAI DB 스키마 변경 없음.** `moai-note-api`는 **자체 저장소**(SQLite)를 쓰며 SeedAI MSSQL에 붙지 않는다.
- 저장 대상: 문서(마크다운 본문 + 제목 + 소유자 + 시각), 리비전(이전 본문 + 시각 + 작성자).
- 소유자 식별은 **토큰에서 얻은** workspace/user 조합. 클라이언트 입력값을 쓰지 않는다.
- 리비전은 보관 상한(개수 또는 기간)을 두어 무한 증가를 막는다.
- 상세 스키마는 I 문서에서 확정한다.

### 3.5 보안/접근제어

**SeedAI 측**: 신규 메뉴·화면·API가 없으므로 `access-control-seed.yaml` 등록 대상이 아니다.

**moai-note-api 측** — 이 요구사항의 보안 핵심이다.

| 항목 | 정책 |
|---|---|
| 인증 | **자체 발급 토큰** 검증(서명·만료). **무인증 경로를 두지 않는다** |
| **MCP 인증** | REST와 **동일 관문**을 통과한다. MCP만 여는 구성을 금지 — R-3328의 전철을 밟지 않는다 |
| 시크릿 취급 | `client_secret`은 **서버 간 호출 전용**. 브라우저에 내려보내지 않는다 — 위젯은 단기 토큰만 |
| 인가 | 문서 소유권을 **서버가** 토큰 기준으로 검증. 클라이언트가 보낸 소유자 식별자는 무시 |
| CORS | 호스트 오리진 **화이트리스트**. 와일드카드 금지 |
| 전송 | HTTPS(F-014). 프록시 종단 시 `X-Forwarded-Proto` 인식 |
| 비밀값 | 토큰 서명키·인증서 경로·비밀번호는 **환경변수 전용**, 저장소 커밋 금지 |
| 로깅 | 인증 실패·권한 위반을 남기되 **토큰·시크릿 원문은 남기지 않는다** |
| 입력 | 본문 크기 상한, 요청 빈도 제한을 둔다(무한 저장 방지) |

**토큰 흐름 (F-013)**

```
[호스트 백엔드]  ──client_id + client_secret + 사용자식별자──►  moai-note-api
                 ◄──────────── 단기 액세스 토큰 ──────────────
       │
       │ 단기 토큰만 전달 (시크릿은 절대 전달하지 않음)
       ▼
   [위젯/브라우저]  ──Bearer 단기 토큰──►  moai-note-api (REST)
   [에이전트]       ──Bearer 단기 토큰──►  moai-note-api (MCP)
```

이 구조 덕분에 `moai-note`는 호스트가 누구인지(SeedAI든 아니든) 알 필요가 없다.
호스트는 자신의 사용자 체계로 인증한 뒤, 그 결과를 사용자 식별자로 넘기기만 하면 된다.

**에디터 측**

- **붙여넣기 정규화**(F-002) — 외부에서 복사한 HTML이 그대로 문서에 들어오지 않도록 지원 블록으로 정규화한다.
- **새니타이즈 경계** — 에디터 DOM은 위젯의 마크다운 주입 경로를 타지 않는다. 에디터가 외부 문자열을 HTML로 주입하는 지점이 있다면 자체 정제를 둔다(I에서 확정).
- **CDN/외부 요청 없음** — 에디터 번들은 호스트 정적 자산으로 **자체 호스팅**한다.

### 6.1 테스트 전략

| 항목 | 방법 |
|------|------|

| 에디터 조작 | 데모 페이지에서 블록 전환·버블 툴바·슬래시 커맨드 육안 확인 |
| **한글 IME** | 조합 중 입력·되돌리기·서식 적용·슬래시 커맨드 오작동 여부 확인 (최우선) |
| 붙여넣기 | 워드/웹페이지/코드 복사 후 붙여넣기 정규화 확인 |
| 임베드 계약 | 마운트/해제 반복 후 DOM·리스너 잔존 확인, 다중 인스턴스 간섭 확인 |
| 지연 로드 | 문서 블록 없는 대화에서 에디터 번들 요청 0건 확인 |
| 폴백 | 번들 로드 차단 상태에서 마크다운 렌더로 표시되는지 확인 |
| 스타일 격리 | 위젯·호스트 화면이 에디터 CSS로 깨지지 않는지 확인 |
| 사본 동기화 | 배포 스크립트 점검에서 차이 0 |
| **API 기능** | REST 엔드포인트별 자동화 테스트(생성·조회·수정·삭제·목록·충돌 409) |
| **토큰 발급** | 유효한 시크릿 → 발급 성공 / 잘못된 시크릿 → 거부 / 폐기된 클라이언트 → 거부 |
| **인증 (최우선)** | 토큰 없음 → 401 / 만료·위조 토큰 → 401 / **MCP 엔드포인트도 동일** 확인 |
| **시크릿 노출** | 위젯이 내려받는 자산·응답에 `client_secret`이 포함되지 않음을 확인 |
| **인가** | 다른 사용자 문서 조회·수정·삭제 시도 → 403 확인 |
| **REST↔MCP 동등성** | 같은 작업을 REST와 MCP로 각각 수행해 **결과가 일치**하는지 확인 |
| **HTTPS** | https 기동 확인 + https 페이지 임베드 위젯에서 혼합 콘텐츠 차단 없이 호출 |
| **CORS** | 화이트리스트 외 오리진에서 차단 확인 |
| 리비전 | 수정 반복 후 이력 조회·되돌리기, 보관 상한 동작 확인 |
| 저장 실패 | 서버 중단 상태에서 편집 내용이 유실되지 않는지 확인 |
| 통합 E2E | 3개 호스트에서 실제 대화 → 문서 열람 → 편집 → **저장** → 재접속 후 내용 유지 |
