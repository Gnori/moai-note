## 1. 요구사항 분석

### 1.1 문제 정의

**호스트 백엔드가 `moai-note-api`에 인증할 표준 수단이 없다.**

R-1030의 인증 설계는 이렇다.

```
[호스트 백엔드] ──client_id + client_secret + subject──► moai-note-api
                ◄──────────── 단기 액세스 토큰 ─────────
      │  단기 토큰만 전달
      ▼
  [브라우저 / 에이전트]
```

`client_secret`은 브라우저에 둘 수 없으므로 **호스트 백엔드가 반드시 중간에 있어야 한다.**
그런데 그 백엔드 쪽 구현이 비어 있다. 지금 상태로는 호스트마다 각자 만들어야 하고, 그러면 이렇게 된다.

| 문제 | 결과 |
|---|---|
| **중복 구현** | 호스트가 늘 때마다 토큰 발급·캐싱·갱신을 다시 짠다 |
| **시크릿 취급이 제각각** | 어떤 호스트는 설정 파일에, 어떤 호스트는 코드에 박는다 |
| **갱신 누락** | 만료 처리를 빼먹으면 한 시간 뒤부터 저장이 실패한다 |
| **계약 변경 전파 불가** | API가 바뀌면 호스트를 전부 찾아 고쳐야 한다 |

R-1030의 위젯 구현 플랜(Task 1)이 **이 문제로 막혀 있다.**

### 1.2 목표 및 성공 지표

**의존성 추가와 설정만으로 호스트 백엔드가 moai-note에 인증할 수 있다.**

선례가 있다 — SeedAI의 `seedai-agent-client-sdk`는 Spring Boot 스타터로 배포되어
호스트가 `application.yml`에 `seedai.client.id/secret`만 넣으면 동작한다. 그 방식을 따른다.

| 목표 | 성공 지표 |
|------|-----------|
| 호스트 구현 부담 제거 | 의존성 + 설정 3~4줄로 토큰 발급이 동작 |
| 시크릿 경계 강제 | SDK를 쓰면 시크릿이 브라우저로 나갈 수 없다 |
| 만료 처리 내장 | 호스트가 갱신 코드를 짜지 않아도 만료로 실패하지 않는다 |
| 계약 변경 흡수 | API 계약 변경 시 SDK 버전만 올리면 된다 |

### 1.3 이해관계자

| 역할 | 요구사항 | 영향도 |
|------|----------|--------|
| 요구자(GnoRi) | `seed-ai-agent-client`처럼 백엔드에서 moai-note-api에 인증하는 수단 | 높음 |
| 호스트 개발자 | 설정만으로 붙고 싶다. 토큰 수명을 신경 쓰고 싶지 않다 | 높음 |
| 보안 | 시크릿이 브라우저·로그·저장소로 새지 않을 것 | 높음 |

### 1.4 제약 조건

- **moai-note 저장소에 둔다** — `moai-note-api`의 클라이언트이므로 계약과 함께 버전이 움직여야 한다.
- **SeedAI에 의존하지 않는다** — SDK는 moai-note API만 안다. 호스트가 SeedAI든 아니든 동일하게 동작한다.
- **참조 구현**: `SeedAI/Seed_AI_Agent/seed-ai-agent-sdk/seed-ai-agent-client`
  (`net.dfocus.seedai.agent:seedai-agent-client-sdk`) — Spring Boot 자동설정 + `application.yml` 설정 + 토큰 저장소 패턴.
  **참조일 뿐 코드를 가져오지 않는다.**
- **첫 대상은 Java/Spring Boot** — SeedAI 호스트(User/Admin 백엔드)가 Spring이다. 다른 런타임용은 후속.
- **사내 Maven 레지스트리 부재** — 배포 방식(로컬 설치 / 소스 의존 / 저장소 구축)을 2.2에서 확정한다.

### 1.5 리스크 분석

| 리스크 | 영향도 | 발생 가능성 | 대응 방안 |
|--------|--------|-------------|-----------|
| **시크릿이 브라우저로 유출** | 높음 | 중간 | SDK가 내주는 값은 **단기 토큰뿐**이도록 설계. 시크릿을 반환하는 메서드를 만들지 않는다 |
| 토큰 캐시가 사용자 간에 섞임 | 높음 | 중간 | 캐시 키를 `(client_id, subject)`로. 전역 단일 토큰을 쓰지 않는다 |
| 만료 직전 토큰을 내주어 호출이 실패 | 중간 | 높음 | 만료 **여유 시간(skew)** 을 두고 미리 갱신 |
| 배포 수단 부재로 호스트가 못 씀 | 높음 | 높음 | 배포 방식을 R 확정 전에 정한다(2.2). 최소한 로컬 설치 절차를 문서화 |
| 시크릿이 로그·예외 메시지에 남음 | 높음 | 중간 | 로깅 시 마스킹. 예외 메시지에 요청 본문을 싣지 않는다 |
| 참조 SDK를 그대로 베껴 SeedAI 종속 유입 | 중간 | 중간 | 패키지·설정 접두사를 moai-note 것으로. SeedAI 클래스를 import 하지 않는다 |

### 1.6 영향 범위

| 모듈 | 위치 | 변경 성격 |
|------|------|-----------|
| `moai-note-client-java` | moai-note (신규) | 신규 모듈 |
| `moai-note-api` | moai-note | 변경 없음 — 기존 토큰 발급 계약을 그대로 쓴다 |
| SeedAI 호스트 백엔드 | 외부 | 의존성 추가 + 설정. **별도 요구사항으로 분리** |

### 2.2 확정이 필요한 사항 (상세화 단계에서 결정)

아래는 **R 확정 전에 답이 필요**하다. 지금 열어 둔다.

| # | 질문 | 선택지 |
|---|---|---|
| 1 | **배포 방식** | (a) 사내 Maven 저장소 구축 (b) `mvn install`로 로컬 설치 (c) 호스트가 소스 서브모듈로 포함 |
| 2 | **SDK 범위** | (a) 토큰 발급만 (b) 토큰 + 문서 API 전체 |
| 3 | **`subject` 규약** | 호스트가 자유롭게 정하는가, 권장 형식을 제시하는가 |
| 4 | **브라우저 전달 경로** | SDK가 컨트롤러(엔드포인트)까지 제공하는가, 호스트가 직접 만드는가 |

> **4번이 특히 중요하다.** 참조 SDK(`seed-ai-agent-client`)는 `ConversationController` 등
> **컨트롤러까지 자동 등록**한다. 같은 방식이면 호스트는 정말 설정만 하면 되지만,
> 경로·인증 정책이 호스트 것과 충돌할 수 있다.

### 2.3 비기능 요구사항

| 구분 | 요구 수준 |
|------|-----------|
| 보안 | 시크릿이 로그·예외·응답에 나타나지 않는다 |
| 신뢰성 | 토큰 만료로 인한 호출 실패가 발생하지 않는다(여유 시간 갱신) |
| 동시성 | 여러 스레드가 동시에 같은 subject의 토큰을 요구해도 발급이 중복되지 않는다 |
| 독립성 | SeedAI 클래스를 참조하지 않는다 |

## 3. 모듈 배치 및 설계 (초안)

### 3.1 모듈 배치

| 기능 | 모듈 | 신규/기존 |
|------|------|-----------|
| F-001~F-009 | `moai-note-client-java` | **신규** |

### 3.2 기술 스택 (초안)

| 구분 | 선택 | 비고 |
|------|------|------|
| 언어 | Java 17+ | 호스트(Spring Boot 3)와 맞춤 |
| 빌드 | Maven | 참조 SDK와 동일 |
| HTTP | Spring `RestClient` 또는 Retrofit | 참조 SDK는 Retrofit. 의존성을 줄이려면 RestClient |
| 자동설정 | Spring Boot AutoConfiguration | `AutoConfiguration.imports` |

### 3.3 설계 개요 (초안)

```
[호스트 Spring Boot 앱]
   │ 의존성 추가 + application.yml 설정
   ▼
[moai-note-client-java]
   ├ config/     자동설정 + 프로퍼티 바인딩
   ├ token/      발급 클라이언트 + 캐시(만료 여유 갱신)
   ├ document/   문서 API 래퍼 (F-007)
   └ error/      API 오류 → 예외 매핑
   │
   │ https + client_secret (서버 간)
   ▼
[moai-note-api] :7100
```

**시크릿 경계**: SDK의 공개 API는 **단기 토큰만** 반환한다. 시크릿을 꺼내는 메서드를 두지 않아,
SDK를 쓰는 한 시크릿이 브라우저로 나갈 수 없게 만든다.

## 4. 범위 제외 (Out of Scope)

- **호스트 백엔드 연동 작업 자체** — SeedAI 저장소 변경이므로 별도 요구사항
- **다른 런타임용 SDK** (Node/Python) — 필요해지면 후속
- **사내 Maven 저장소 구축** — 배포 방식이 (a)로 정해지면 인프라 과제로 분리
- **프런트엔드용 클라이언트** — 브라우저는 `embed.js`가 담당(R-1030)

## 5. 테스트 계획 (초안)

| 항목 | 방법 |
|------|------|
| 토큰 발급 | 실제 `moai-note-api` 기동 상태에서 발급 성공 확인 |
| 캐시 | 같은 subject 연속 요청 시 API 호출이 1회인지 확인 |
| 사용자 격리 | 다른 subject 요청이 서로 다른 토큰을 받는지 확인 |
| 만료 갱신 | 짧은 TTL로 설정 후 여유 시간 안에 자동 갱신되는지 확인 |
| 동시성 | 같은 subject로 동시 요청 시 발급이 중복되지 않는지 확인 |
| **시크릿 유출** | 로그·예외 메시지·응답에 시크릿이 없는지 확인 |
| 자동설정 | 의존성만 추가한 최소 앱에서 빈이 등록되는지 확인 |
